# 对齐稿

## 一、需求概述

建设一套独立的**资源中心管理后台**，为已有应用端补齐后台类目管理能力，覆盖"频道 → 分类 → 条目"三层类目结构，其中条目层支持多级级联维度定义（如学段→年级/学科）。

## 二、建设范围

### （一）一期范围

- **类目管理 · 频道管理**：频道添加 / 删除（含"已在分类中使用不可删"约束）/ 修改 / 查询 / 列表
- **类目管理 · 分类管理**：添加分类 / 添加子分类 / 删除（已上架不可删）/ 修改 / 上架 / 下架 / 查询 / 列表；分类关联条目时，勾选条目后若该条目下存在已上架子条目，展示对应子条目并可继续勾选
- **类目管理 · 条目管理**：添加条目 / 添加子条目 / 修改 / 上架 / 下架 / 删除（已上架或被其他分类引用不可删）/ 查询 / 列表；子条目项支持上/下架（已上架不可删）；条目支持"下级条目 / 条目值"两种类型，实现如 [图片1.png](file:///d:/claudeCode/AIProject/ShitPM2/input/%E5%9B%BE%E7%89%871.png) 所示的多级级联（例：学段=小学→年级=一/二/三/四/五/六，学科=数学/语文/英语；学段=初中→年级=七/八/九，学科=数学/语文/英语/地理/物理/化学）
- **审批管理 · 审批列表**：查看 / 审批（通过或驳回）资源审批记录；桂教通超管查看全量并可审批，其他机构人员仅查看本机构记录
- **角色区分**：桂教通超管（全模块全操作）与机构人员（仅资源管理+审批管理，数据限本机构）；机构人员新增资源需超管审批通过后自动发布，超管新增资源无需审批
- **导航结构**：按 md 目录层级组织
  - 类目管理（仅桂教通超管可见）
    - 频道管理
    - 分类管理
    - 条目管理
  - 资源管理
    - 资源列表
  - 审批管理
    - 审批列表
  - 硬件与服务管理（仅桂教通超管可见）
    - 智慧硬件与服务
    - 预约记录

### （二）二期范围（如有）

- 暂无（后续可能纳入"资源本身管理"）

### （三）明确不做

- 登录模块
- 资源本身的管理（上传 / 下载 / 删除 / 修改 / 搜索 / 分类打标 / 标签 / 分享）——即 [资源中心管理后台.md](file:///d:/claudeCode/AIProject/ShitPM2/input/%E8%B5%84%E6%BA%90%E4%B8%AD%E5%BF%83%E7%AE%A1%E7%90%86%E5%90%8E%E5%8F%B0.md) 中被 `<!-- -->` 注释掉的资源管理部分
- 对外接口契约的交付（接口由后端团队独立设计）

## 三、建设方式

**类型**：`new_build`（全新建设）

**判断依据**：

- 无现有后台系统作为挂载点
- 不复用现有登录/权限体系（本期不做）
- 后台侧从 0 建设菜单、页面、字段与状态机
- 数据侧存在"已有应用端在用"的兼容点（详见业务阶段）

## 四、业务阶段

**已有应用端在用**：应用端已在消费类目数据，本期属于"补齐后台管理能力"。设计阶段需考虑：

- 现有类目数据（频道 / 分类 / 条目）的**兼容性**（字段是否已有存量、编码规则是否与现网一致）
- 上架 / 下架状态与应用端可见性的**同步契约**（"上架成功后才可在应用端获取到"，"下架成功后应用端不可获取"）
- 不涉及应用端 UI 变更
